# 变更协议

PRD 流程完成后，用户提出新需求/变更时的处理规则。**只从变更落点向下游重跑，禁止全量重跑。**

## 触发条件

进度文件「闸口状态」为「已完成」，且用户提出：
- 新增/删除功能
- 修改已确认的业务流程或规则
- 最终PRD/原型定稿后的调整

## 处理流程

1. **拆解变更句**：把用户的变更描述拆成具体变更点。
2. **定位落点**：判断变更影响哪个阶段的产物。
   - 影响业务流程/功能模块/用户场景 → 落点 = 阶段1（概要PRD）
   - 仅影响页面交互/布局 → 落点 = 阶段2（原型）
   - 仅影响字段规则/状态/边界 → 落点 = 阶段4（详细PRD草稿）
3. **向下游重跑**：从落点阶段开始，只更新受影响的产物，下游跟着刷新。
   - 落点阶段1 → 概要改 → 原型改 → 用户自审(3)重审 → 详细PRD草稿改 → 三审(5/6)重审 → 阶段7重新汇总决策+定稿
   - 落点阶段2 → 原型改 → 用户自审(3)重审 → 详细PRD草稿(4)同步 → 视情况重跑三审
   - 落点阶段4 → 详细PRD草稿改 → 三审(5/6)重审 → 阶段7定稿
4. **是否重跑三审**：
   - 小改（措辞、单字段）→ 可只更新最终PRD，不必重跑三审，但要在回填表补一条变更记录
   - 大改（加功能、改流程）→ 必须重跑三审（至少研发评审重估工量）
5. **R/C-编号顺延**：确认记录与变更项继续追加，不清零历史。

## 落点判断示例

```
变更「加一个批量导出功能」
→ 新功能 = 落点阶段1（概要加模块+页面）
→ 原型加导出交互（阶段2）
→ 用户自审（阶段3）重审
→ 详细PRD草稿补导出规则（阶段4）
→ 重跑三审（5/6，研发重估工量）
→ 阶段7重新汇总决策+定稿

变更「导出按钮挪到右上角」
→ 纯交互 = 落点阶段2（改原型）
→ 用户自审（阶段3）确认后同步最终PRD，无需重跑业务/研发评审

变更「导出上限1万→5万」
→ 规则调整 = 落点阶段4（改草稿字段规则）
→ 研发评审（阶段6）重估（可能触发性能风险）→ 阶段7定稿
```

## 禁止

- 全量重跑所有阶段（浪费且丢失历史）
- 跳过拆解直接改最终PRD
- 变更原型却不同步PRD（导致原型与PRD脱节）
- 大改却跳过三审重审（评审失去意义）
- 清空 R/C-编号历史
