# 阶段4：一审·用户自审

**产物**：`03-用户自审意见.md`

**目标**：三审的第一审。用户亲自试用原型 + 读详细PRD草稿，以"我自己"的立场提出意见。这是用户主导的环节——AI 只负责记录，不代判、不辩解。

## 执行动作

1. 请用户打开 `prototype/index.html` 试用，并翻看 `02-详细PRD草稿.md`。
2. 收集用户意见，逐条记录到 `03-用户自审意见.md`。每条含：
   - 针对什么（哪个页面/哪个功能/PRD哪节）
   - 问题/想法是什么
   - 期望怎样
3. **只记录，不在本阶段改**：用户自审的意见先攒着，和阶段5/6的评审意见一起，到阶段7统一决策修改。
4. 停在闸口。

## 记录纪律

- **不遗漏**：用户提的每条都记
- **不代判**：用户说什么记什么，不争辩（除非涉及组件库铁律，说明即可）
- **不当场改**：本阶段是"收集一审意见"，不是"改"。改在阶段7（三审汇总后统一改）
- **区分类型**：标注每条是「原型交互」「PRD规则」还是「需求变更」

## 产物模板：03-用户自审意见.md

```markdown
# <产品名> 一审·用户自审意见
> 审校人：用户本人｜时间：<时间>
> 审校对象：prototype/ + 02-详细PRD草稿.md

## 用户意见清单
| 编号 | 针对 | 问题/想法 | 期望 | 类型 |
|---|---|---|---|---|
| A-01 | 考试列表页 | 找不到申报入口 | 顶部加申报按钮 | 原型交互 |
| A-02 | PRD 3.2 | 报名截止规则没写清 | 明确截止后能否补报 | PRD规则 |

（类型：原型交互 / PRD规则 / 需求变更）

## 一审小结
- 共 N 条意见（原型交互 X / PRD规则 Y / 需求变更 Z）
- 待阶段7与业务评审、研发评审意见汇总后统一决策
```

三、确认后进入阶段5：二审·业务视角评审（派独立子代理，以服务用户身份代入业务场景挑问题）
