# 阶段4：服务用户视角评审（独立 subagent）

**产物**：`04-用户视角评审报告.md`

**铁律**：评审意见**必须交用户决策**，AI **禁止自行修改**原型/PRD。

## 目标

跳出"设计者"立场，用**独立 subagent**以真实"服务用户"身份代入业务场景走一遍原型，挑出使用障碍、流程断点、体验问题。评审完**停在闸口**，把问题交给用户，由用户决定改不改、怎么改。

## 为什么用独立 subagent

主对话的 Claude 是原型的"作者"，天然有立场偏差。独立 subagent 不带作者包袱，以**用户身份**代入，更客观。

## 执行动作

1. 从 `02-概要PRD.md` 提取**目标用户角色**和**用户场景**（S-01…）
2. 用 Agent 工具启动独立 subagent，传入评审任务（见下方协议）
3. subagent 产出评审意见
4. **写评审报告**：`04-用户视角评审报告.md`（只含 subagent 意见，不含用户裁决）
5. **停在闸口**：展示≤5条典型问题，**问用户**：
   - 这些问题认可吗？
   - 改哪些、不改哪些？
   - 接受的怎么改？（用户给方向，不是 AI 代答）
6. 用户回复后，把裁决追加到报告「## 用户裁决」段，记 R-编号到进度文件
7. 进阶段5（根据用户裁决更新原型 + 输出详细PRD）

## subagent 调用协议

用独立 subagent（通用型），给它这样的任务提示：

```
你是【<产品名>的目标用户：<角色，如"考务管理员">】。不是产品设计者，是每天要用这个系统干活的一线用户。

请打开原型逐页试用：outputs/<产品名>/prototype/（读取各 HTML 文件内容理解交互）。

代入以下真实业务场景，逐个走一遍：
<从概要PRD粘贴 S-01…场景清单>

以挑剔的一线用户视角，回答：
1. 每个场景我能否顺畅完成任务？卡在哪一步？
2. 有没有我预期有、但原型里找不到的功能/入口？
3. 有没有看不懂的术语、图标、操作？
4. 流程是否符合我的真实工作习惯？有没有多余步骤？
5. 异常情况（数据为空、操作失败、权限不足）原型有没有考虑？

输出格式：
## 严重问题（阻塞任务完成，P0）
| 编号 | 页面 | 问题 | 用户感受 | 建议改进 |
|---|---|---|---|---|
| E-01 | 考试列表 | 无"申报"入口 | 不知道怎么开始 | 列表顶部加"申报考试"主按钮 |

## 体验问题（能完成但难受，P1）
| 编号 | 页面 | 问题 | 建议改进 |
|---|---|---|---|

## 缺失项（预期有但没有）
| 编号 | 缺什么 | 影响场景 |
|---|---|---|

## 做得好的地方（客观肯定，1-2条即可）
- <具体>

要具体、要挑刺，不要泛泛表扬。你的价值在于发现设计者看不到的使用障碍。
```

## 闸口话术

```
【阶段4完成】独立评审发现 X 个问题（完整见 04-用户视角评审报告.md）

一、典型问题：
  1. E-01（严重）：<问题> → subagent 建议：<改法>
  2. P1-02（体验）：<问题> → subagent 建议：<改法>
  
二、待你裁决（必须回复，AI 禁止代答）：
  1. 这些问题认可吗？
  2. 改哪些、不改哪些？（回复编号，如"接受 E-01/P1-02"）
  3. 接受的怎么改？（给个方向即可，如"E-01 加主按钮"）
  
我会把你的裁决记入报告（R-编号），然后阶段5根据裁决改原型 + 输出详细PRD。
```

## 质量把关

- 评审≥3条（<3条重派 subagent）
- 至少1条 P0 或 P1（纯 P2 = 没找真问题）
- **禁止主对话自评**（受污染）
- **禁止 AI 自行决定改不改、怎么改**——必须用户裁决后才写入「用户裁决」段
