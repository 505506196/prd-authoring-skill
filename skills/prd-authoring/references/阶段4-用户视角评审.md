# 阶段 4：服务用户视角评审（独立 subagent）

**目标**：跳出"设计者"立场，用**独立 subagent**以真实"服务用户"身份代入业务场景走一遍原型，挑出使用障碍、流程断点、体验问题。这不是自我表扬，是找茬。

## 为什么用独立 subagent

主对话的 Claude 是原型的"作者"，天然有立场偏差（倾向认为自己做的没问题）。独立 subagent 不带作者包袱，以**用户身份**代入，更客观。

## 执行动作

1. 从 `01-概要PRD.md` 提取**目标用户角色**和**用户场景**（S-01…）。
2. 用 Agent/Task 工具启动一个独立 subagent，传入评审任务（见下方协议）。
3. subagent 产出评审意见，主对话把它写入 `03-用户视角评审.md`。
4. 在对话向用户展示评审发现的 TOP 问题。
5. 停在闸口——问用户哪些问题要在进入详细PRD前先解决。

## subagent 调用协议

用独立 subagent（通用型即可），给它这样的任务提示：

```
你是【<产品名>的目标用户：<角色，如"考务管理员">】。不是产品设计者，是每天要用这个系统干活的一线用户。

请打开原型逐页试用：outputs/<产品名>/prototype/index.html（读取各 HTML 文件内容理解交互）。

代入以下真实业务场景，逐个走一遍：
<从概要PRD粘贴 S-01…场景清单>

以挑剔的一线用户视角，回答：
1. 每个场景我能否顺畅完成任务？卡在哪一步？
2. 有没有我预期有、但原型里找不到的功能/入口？
3. 有没有看不懂的术语、图标、操作？
4. 流程是否符合我的真实工作习惯？有没有多余步骤？
5. 异常情况（数据为空、操作失败、权限不足）原型有没有考虑？

输出格式：
## 严重问题（阻塞任务完成）
- [页面] 问题 → 用户实际感受 → 建议
## 体验问题（能完成但难受）
- ...
## 缺失项（预期有但没有）
- ...
## 做得好的地方（客观肯定，1-2条即可）
- ...

要具体、要挑刺，不要泛泛表扬。你的价值在于发现设计者看不到的使用障碍。
```

## 产物模板：03-用户视角评审.md

```markdown
# <产品名> 服务用户视角评审

## 严重问题（阻塞任务，P0）
| 编号 | 页面 | 问题 | 用户感受 | 建议 |
|---|---|---|---|---|
| E-01 | | | | |

## 体验问题（P1）
| 编号 | 页面 | 问题 | 建议 |
|---|---|---|---|

## 缺失项（预期有但没有）
| 编号 | 缺什么 | 影响场景 |
|---|---|---|

- <客观肯定>

## 评审结论
- 严重问题 N 项，体验问题 M 项，缺失 K 项
- 进入详细PRD前建议先解决：<E编号清单>
```

## 闸口话术

```
【阶段4完成】用户视角评审已写入 outputs/<产品名>/03-用户视角评审.md

一、评审结论（以<用户角色>身份代入）：
- 严重问题 N 项：<TOP2>
- 体验问题 M 项
- 缺失项 K 项：<TOP2>

二、待你裁决：
1. 这些问题你认可吗？
2. 哪些在进入详细PRD前必须解决（回原型/概要改）？哪些记录到PRD里后续解决？
   建议：严重问题(E)先解决，体验问题(P1)记入PRD
3. 是否需要改原型后重评审？

三、确认后进入阶段5：输出详细PRD（逐条回填阶段3反馈+阶段4评审问题）
```
