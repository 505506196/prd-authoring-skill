# 阶段7：三审汇总决策 + 最终交付

**产物**：`06-三审汇总与裁决.md` + `07-最终详细PRD.md` + 更新后的 `prototype/`（最终版）

**目标**：把三审（用户自审+业务评审+研发评审）意见汇总成一张表，**交用户统一决策**；用户裁决后，按裁决更新原型、输出最终详细PRD。这是全流程收口。

**铁律**：三审意见必须汇总交用户决策，**AI 禁止自行决定改不改、怎么改**；用户全部确认后才动手改。

## 执行动作（严格按序）

### 第一步：汇总三审意见
1. 读三审产物：`03-用户自审意见.md`、`04-业务视角评审.md`、`05-研发评审.md`。
2. 汇总成一张总表，写入 `06-三审汇总与裁决.md`（模板见下）。合并同类项、标注冲突项。

### 第二步：交用户统一决策（停闸口）
3. 在对话展示汇总表（按严重度排序，P0在前），**逐条或分组问用户**：
   - 采纳吗？（采纳/暂缓/不采纳）
   - 采纳的怎么改？（用户给方向，AI 不代答）
   - 冲突项（如业务要加功能、研发说工量大）请用户拍板
4. **等用户全部裁决**。把裁决填入 `06-三审汇总与裁决.md` 的「用户裁决」列，记 R-编号到进度文件。

### 第三步：按裁决更新原型
5. 对"采纳且涉及原型"的条目，按用户指定改法修改 `prototype/`（仍遵循组件库铁律）。
6. 改完请用户验收：「原型已按裁决更新，请点 prototype/index.html 复看」。用户确认 OK。

### 第四步：输出最终详细PRD
7. 基于 `02-详细PRD草稿.md`，吸收所有采纳的裁决，输出 `07-最终详细PRD.md`：
   - 含「三审回填」章节：逐条列三审意见 + 用户裁决 + 落地位置
   - 采纳项体现在正文，暂缓/不采纳项在回填表说明原因
8. 停在闸口做终审确认。

### 第五步：交付与收尾
9. 用户确认最终PRD无误 → 更新进度为「已完成」→ **发 finish 埋点**。

## 质量把关

- 三审意见**一条不漏**汇总（对齐三份报告的编号）
- **每条必须有用户裁决**——AI 禁止代答
- 采纳且涉及原型的，原型必须实际改并经用户验收
- 最终PRD 的「三审回填」表与汇总裁决表编号对齐
- finish 只在用户确认最终PRD后发一次
