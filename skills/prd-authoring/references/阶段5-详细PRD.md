# 阶段 5：详细 PRD

**目标**：把概要PRD + 原型 + 用户反馈 + 用户视角评审，收敛成一份**研发可直接读的详细PRD**。字段级、状态级、规则级都要讲清。

## 执行动作

1. 读齐上游全部产物：`01-概要PRD.md`、`prototype/`、`02-原型反馈.md`、`03-用户视角评审.md`。
2. **先做回填表**（铁律3）：把阶段3反馈 + 阶段4评审的每一条，逐条标注处理方式，写进详细PRD的"评审回填"章节。
3. 逐功能模块展开详细需求：功能描述、交互流程、字段规则、状态流转、边界与异常。
4. 对原型已体现的交互，引用原型页面（"见 prototype/xxx.html"），不重复画。
5. 业务规则有空缺 → 对话共创（禁止 AI 脑补规则）。
6. 写入 `04-详细PRD.md`。
7. 停在闸口。

## 回填要求（铁律3，最重要）

详细PRD**必须**有一章逐条回应上游评审，每条给结论：

| 来源 | 编号 | 问题 | 处理 | 说明 |
|---|---|---|---|---|
| 用户反馈 | F-01 | ... | 已解决/暂缓/不采纳 | 在PRD哪节体现/为何不采纳 |
| 视角评审 | E-01 | ... | 已解决/暂缓/不采纳 | ... |

**禁止**：无视评审结论，另写一份和评审脱节的PRD。

## 共创要求

详细PRD 涉及大量业务规则（校验规则、状态流转、权限矩阵、异常处理）。对每个规则空缺：
- 在对话展示问题 + 建议默认值
- 拿到用户方向再写入，标 `[已确认-R编号]`
- 允许"先按默认，后续可调"，但不允许 AI 编造硬规则当成需求

## 闸口话术

```
【阶段5完成】详细PRD已写入 outputs/<产品名>/04-详细PRD.md

一、PRD结论：
- 详细展开 N 个功能模块
- 回填上游评审 M 条（已解决X/暂缓Y/不采纳Z）
- 明确边界 K 项

二、待你裁决：
1. 详细需求准确吗？有没有理解偏差的规则？
2. 评审回填的处理方式（暂缓/不采纳项）你认可吗？
3. 字段规则、状态流转有没有要补的？

三、确认后进入阶段6：研发需求评审（技术可行性/工量/边界/依赖/风险）
```
