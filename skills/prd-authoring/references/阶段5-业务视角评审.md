# 阶段5：二审·业务视角评审（独立子代理）

**产物**：`04-业务视角评审.md`

**目标**：三审的第二审。派**独立 subagent**以真实"服务用户/业务方"身份代入业务场景走原型+读PRD草稿，挑出团队内部看不见的使用障碍、流程断点、业务不合理处。

**铁律**：必须用独立 subagent（不受主对话设计意图污染）；评审只出意见，**不改**——改在阶段7。

## 执行动作

1. 从 `01-概要PRD.md` 提取目标用户角色和用户场景（S-01…）。
2. 用 Agent 工具启动独立 subagent，传入评审任务（见下方协议）。
3. subagent 产出评审意见，主对话写入 `04-业务视角评审.md`。
4. 在对话向用户展示评审发现的 TOP 问题（**只告知，不决策**——决策在阶段7）。
5. 停在闸口。

## subagent 调用协议

用独立 subagent（通用型），任务提示：

```
你是【<产品名>的目标用户：<角色，如"考务管理员">】。不是产品设计者，是每天要用这个系统干活的一线业务人员。

评审对象：
- 原型：outputs/<产品名>/prototype/（读各 HTML 理解交互）
- 详细PRD草稿：outputs/<产品名>/02-详细PRD草稿.md

代入以下真实业务场景，逐个走一遍：
<从概要PRD粘贴 S-01…场景清单>

以挑剔的一线业务视角，回答：
1. 每个场景我能否顺畅完成任务？卡在哪一步？
2. 有没有我预期有、但原型/PRD里找不到的功能/入口？
3. 有没有看不懂的术语、图标、操作？
4. 业务流程符合我的真实工作习惯吗？有没有多余步骤、缺失环节？
5. 业务规则（PRD里的）合理吗？有没有和实际业务冲突的？
6. 异常情况（数据为空、操作失败、权限不足）有没有考虑？

输出格式：
## 严重问题（阻塞业务，P0）
| 编号 | 针对 | 问题 | 业务影响 | 建议 |
|---|---|---|---|---|
| B-01 | 报名流程 | 无补报机制 | 漏报考生无法救济 | 加补报窗口期规则 |

## 体验/流程问题（P1）
| 编号 | 针对 | 问题 | 建议 |

## 缺失项（业务预期有但没有）
| 编号 | 缺什么 | 影响场景 |

## 做得好的地方（客观，1-2条）
- <具体>

要具体、要挑刺，站一线业务立场，别泛泛表扬。
```

## 质量把关

- 评审≥3条（<3条重派 subagent）
- 至少1条 P0 或 P1
- 禁止主对话自评
- **本阶段不决策、不修改**——只产出评审意见，决策统一在阶段7
