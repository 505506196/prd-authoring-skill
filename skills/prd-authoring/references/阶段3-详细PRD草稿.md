# 阶段3：详细PRD草稿

**产物**：`02-详细PRD草稿.md`

**目标**：把概要PRD + 原型收敛成一份**详细PRD草稿**——字段级、状态级、规则级讲清。这是供三审（阶段4/5/6）评审的对象。**是草稿，不是终稿**；终稿在阶段7根据三审裁决产出。

## 执行动作

1. 读齐上游：`01-概要PRD.md`、`prototype/`。
2. 逐功能模块展开详细需求：功能描述、交互流程、字段规则、状态流转、边界与异常。
3. 对原型已体现的交互，引用原型页面（"见 prototype/xxx.html"），不重复画。
4. 业务规则有空缺 → 对话共创（禁止 AI 脑补规则）。
5. 写入 `02-详细PRD草稿.md`。
6. 停在闸口。

## 共创要求

详细PRD 涉及大量业务规则（校验规则、状态流转、权限矩阵、异常处理）。对每个规则空缺：
- 在对话展示问题 + 建议默认值
- 拿到用户方向再写入，标 `[已确认-R编号]`
- 允许"先按默认，后续可调"，但不允许 AI 编造硬规则当成需求

## 闸口话术

```
【阶段3完成】详细PRD草稿已写入 outputs/<产品名>/02-详细PRD草稿.md

一、草稿结论：
- 详细展开 N 个功能模块
- 明确字段规则、状态流转、边界异常
- 明确边界 K 项

二、待你裁决：
1. 详细需求准确吗？有没有理解偏差的规则？
2. 字段规则、状态流转有没有要补的？

三、确认后进入三审三校：
   阶段4 你自己试用原型+读草稿（一审·用户自审）
   → 阶段5 业务视角评审（独立子代理）
   → 阶段6 研发需求评审（独立子代理）
   → 阶段7 汇总三审意见交你决策，输出最终PRD+原型
```
