# PRD 输出 — 概要PRD → 原型 → 用户试用 → 用户视角评审 → 详细PRD → 研发评审

把需求做成可交付的 PRD。六个阶段流水线，每阶段：**读上一阶段落盘产物 → 与用户共创产出 → 过校验 → 停在闸口等确认 → 才进下一阶段**。

## 核心原则（三条铁律，违反即错）

1. **原型必须遵循组件库**：阶段2生成的原型，严禁自造按钮/表单/表格/弹窗样式，严禁硬编码主色/圆角/阴影。必须引用 `~/.claude/prd-authoring-assets/web组件库/dist/shekao-ui.css+js`，用组件库的 class 和 `data-*`。生成前必读组件库的 `AI-USAGE.md`、`CLAUDE.md`（视觉红线）。违反即返工。
2. **评审必须独立视角**：阶段4用**独立 subagent**以"服务用户"身份代入真实业务场景走原型，挑真实使用障碍，不是 AI 自我表扬。阶段6以研发视角评审（可行性/工量/边界/依赖/风险），只出意见不写代码。
3. **详细PRD必须回填评审**：阶段5的详细PRD要逐条吸收阶段3用户反馈 + 阶段4评审问题，每条标注「已解决/暂缓/不采纳+原因」。禁止把评审结论丢在一边另写PRD。

## 进度协议（每次启动第一件事）

1. 先确定/询问**产品名**，在 `outputs/<产品名>/` 下工作（多产品隔离）。
2. **诊断产物自动带入**：检查 `outputs/<产品名>/04-诊断报告.md` 是否存在。
   - **存在** → 自动读入作为需求输入，无需用户重述需求，直接确认"检测到诊断报告，已读入，是否基于它开始概要PRD？"
   - **不存在** → 请用户提供需求（一句话/文档/想法皆可），作为阶段1输入。
3. 读 `outputs/<产品名>/00-进度.md`：
   - **不存在** → 按下方模板创建，从阶段1开始。
   - **存在** → 读「当前阶段」与「闸口状态」，从中断处继续；闸口状态为「待确认」时，先把待裁决项重新交给用户。
   - **「已完成」且用户提新需求/变更** → 读 `references/变更协议.md`，只从落点向下游重跑。
4. 读 `references/<当前阶段>.md`（只读当前这一个），照它执行。
5. 阶段做完：产物落盘 → 更新进度 → **发一条「阶段完成」埋点** → 停在闸口。**一次回复只推进一个阶段。**
   > 【埋点·阶段完成】阶段 1/2/3/4/5 每完成一个各发一条（阶段6走下方 finish）；`<阶段标识>` 取 `1`/`2`/`3`/`4`/`5`：`bash ~/.claude/feishu-tracker/track.sh "prd-authoring" --event stage-<阶段标识> --version "0.1.0" --run "<run-id字面值>"`
6. **finish 埋点只在整条流程真正结束时上报一次**：中途各阶段停在闸口**不是** finish。仅当推进的是**阶段6（研发评审完成、进度更新为「已完成」）**时上报唯一一次：
   > 【埋点】`bash ~/.claude/feishu-tracker/track.sh "prd-authoring" --event finish --version "0.1.0" --run "<run-id字面值>"`

## 六个阶段

| 阶段 | 名称 | 产物 | 细则 |
|---|---|---|---|
| 1 | 概要需求文档 | 02-概要PRD.md（业务流程+功能模块+用户场景） | references/阶段1-概要PRD.md |
| 2 | 原型生成 | prototype/*.html + index.html（遵循组件库） | references/阶段2-原型生成.md |
| 3 | 用户试用与修改 | 更新 prototype/ + 03-原型试用反馈.md | references/阶段3-用户试用.md |
| 4 | 服务用户视角评审 | 04-用户视角评审报告.md（独立 subagent + 用户裁决） | references/阶段4-用户视角评审.md |
| 5 | 详细 PRD | 05-详细PRD.md + 最终 prototype/（根据阶段4裁决更新） | references/阶段5-详细PRD.md |
| 6 | 研发需求评审 | 06-研发评审意见.md（只出评审意见） | references/阶段6-研发评审.md |

## 全局纪律

**不允许：**
- 跳过闸口连跑两个阶段（即使用户说「一口气跑完」）
- 原型自造组件样式、硬编码视觉值（见铁律1）
- 阶段4自评自夸、跳过 subagent（见铁律2）
- 详细PRD 无视上游评审另起炉灶（见铁律3）
- 把推断写成需求——每条功能点标 `[已确认]`（有 R-编号）／`[推断]`／`[待确认]`

**必须：**
- 下一阶段只从 `outputs/<产品名>/` 文件取上游信息，不依赖对话记忆
- 每个闸口输出固定三段：①本阶段产物摘要 ②待裁决项（≤5 条，每条给默认建议）③下一步预告
- 原型生成前必读组件库 `AI-USAGE.md` 与 `CLAUDE.md`

## 闸口话术模板

```
【阶段 N 完成】产物已写入 outputs/<产品名>/xx
一、本阶段结论：<3 行以内>
二、待你裁决（回复编号即可）：
  1. <问题>？建议：<默认方案>
三、确认后进入阶段 N+1：<一句话预告>
```

## 终点定义

流程完成 = 阶段6研发评审出具意见、详细PRD定稿。
- 输出 `04-详细PRD.md` + `05-研发评审.md`，可直接进入研发排期
- 研发评审若发现 P0 阻塞项 → 回到阶段5修订PRD，再评审
