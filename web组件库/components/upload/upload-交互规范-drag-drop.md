# 上传交互规范 — 拖拽上传与文件队列

> **本文件解决「文件上传的拖拽交互与队列管理」问题**：拖拽区域高亮、文件校验时机、多文件队列状态、失败重试。

---

## 一、设计目标

| 目标 | 表现 |
|------|------|
| **拖入有感** | 文件拖入区域时边框高亮，明确告知可放置 |
| **校验前置** | 文件类型/大小在选择后立即校验，不等上传完再报错 |
| **进度可见** | 每个文件独立显示上传进度 |
| **失败可重试** | 上传失败的文件可单独重试，不影响其他文件 |

---

## 二、拖拽上传交互

### 2.1 拖拽状态机

```
[默认态] ──文件拖入浏览器窗口──→ [全局拖拽提示]
                                       │
                              文件拖入上传区域
                                       ↓
                               [区域高亮态]
                                       │
                              释放文件 / 拖出区域
                                ↓              ↓
                         [开始上传]      [恢复默认态]
```

### 2.2 视觉状态

| 状态 | 视觉表现 |
|------|---------|
| 默认 | 虚线边框 + 上传图标 + 提示文字 |
| 拖入区域（dragover） | 边框变为 `var(--primary-600)` 实线 + 背景 `var(--primary-50)` |
| 拖出区域（dragleave） | 恢复默认 |
| 禁用态 | 灰色虚线边框，不响应拖拽 |

### 2.3 实现要点

- 监听 `dragenter`/`dragover`/`dragleave`/`drop` 四个事件
- `dragover` 必须 `preventDefault()` 才能接收 `drop`
- `dragleave` 需要判断是否真正离开区域（子元素触发的 leave 要忽略）
- `drop` 后立即 `preventDefault()` 阻止浏览器打开文件

## 三、文件校验

### 3.1 校验时机

| 时机 | 校验内容 |
|------|---------|
| 选择/拖入后立即 | 文件类型、文件大小、文件数量上限 |
| 上传前 | 同名文件检测、自定义业务校验 |

### 3.2 校验规则

| 规则 | 不通过时行为 |
|------|-------------|
| 文件类型不匹配 | 该文件不加入队列，Toast 提示「不支持的文件格式」 |
| 文件大小超限 | 该文件不加入队列，Toast 提示「文件大小超过 Xmb」 |
| 文件数量超限 | 超出的文件不加入队列，Toast 提示「最多上传 N 个文件」 |
| 同名文件 | 提示「文件已存在，是否覆盖？」 |

---

## 四、文件队列管理

### 4.1 队列状态

| 状态 | 图标 | 说明 |
|------|------|------|
| 等待中 | 灰色时钟 | 排队等待上传 |
| 上传中 | 进度条 | 显示百分比进度 |
| 上传成功 | 绿色勾 | 可预览/下载/删除 |
| 上传失败 | 红色叉 | 显示失败原因 + 重试按钮 |

### 4.2 并发控制

- 默认并发数：3（同时上传 3 个文件）
- 超出并发的文件排队等待
- 某文件完成后自动开始下一个

### 4.3 操作

| 操作 | 行为 |
|------|------|
| 删除（上传中） | 取消上传请求 + 从队列移除 |
| 删除（已完成） | 从队列移除 + 调用删除接口 |
| 重试（失败） | 重新发起该文件的上传请求 |
| 全部重试 | 重试所有失败文件 |
