# 徽章交互规范 — 数字溢出 99+ / 实时更新动效 / 清零

> **本文件解决「未读数量过多撑爆容器」「实时更新没有动画用户感知不到」「清零后角标残留」三类问题。**
>
> 视觉规范见 [`../../badge.md`](../../badge.md)。

---

## 一、设计目标

| 目标 | 表现 |
|------|------|
| **不撑容器** | 数字超过 99 显示 99+，超过 999 显示 999+ |
| **更新有反馈** | 数字变化时角标抖动 / 主体微动画 |
| **清零自然** | 数量降为 0 时角标淡出消失 |
| **动效克制** | 不允许常驻动画 / 闪烁吸引注意 |

---

## 二、数字溢出

### 2.1 显示规则

| 实际值 | 显示 |
|-------|------|
| 0 | **不显示**角标（参考"清零自然"原则）|
| 1–99 | 实际数字 |
| 100–999 | "99+" |
| > 999 | "999+" |
| 业务方传入字符串 | 直接显示（如"NEW"、"HOT"）|

### 2.2 max 参数

- 业务方可指定 max（默认 99）
- 超过 max 显示 "max+"（如 max=999 时 1500 显示"999+"）
- max 不允许小于 9

### 2.3 角标宽度

- 单字符（"1"–"9"）：圆形 18×18
- 两位数及以上（"99"、"99+"）：胶囊 18× 自适应宽度
- padding 左右各 4px（参考 badge.md 第四节）

---

## 三、实时更新

### 3.1 数字变化动效

| 变化类型 | 动画 |
|---------|------|
| **+1（如收到新消息）** | 角标 `scale 1→1.2→1` 200ms + 容器主体抖动一次 200ms |
| **+N（批量更新）** | 同上，但抖动幅度不变（一次反馈即可，避免连续抖）|
| **数字变小（已读了一些）** | 仅角标 `fade 0.6→1` 150ms，无抖动 |
| **数字相同** | 不触发动画 |

### 3.2 抖动动画

```css
@keyframes badge-bump {
  0% { transform: scale(1); }
  30% { transform: scale(1.2); }
  100% { transform: scale(1); }
}
```

- 持续 200ms cubic-bezier(.4,0,.2,1)
- 仅角标 scale，不影响下层元素
- 同时父元素可启用主体抖动（业务方可关闭）

### 3.3 防抖（避免高频更新）

- 100ms 内多次更新合并为一次动画
- 避免轮询接口频繁触发抖动

### 3.4 增量提示（可选）

- 业务方启用 `showIncrement=true` 时
- 角标右上方浮出 "+N" 文字 500ms 后淡出
- 用于强调"刚才新增了多少"

## 四、清零

### 4.1 触发清零

| 场景 | 行为 |
|------|------|
| 数量从 N → 0 | 角标淡出 + 缩小 200ms |
| 用户主动标记已读 | 同上 |
| 业务方调用 reset | 同上 |

### 4.2 淡出动画

```css
@keyframes badge-fade-out {
  from { opacity: 1; transform: scale(1); }
  to { opacity: 0; transform: scale(.7); }
}
```

- 持续 200ms cubic-bezier(.4,0,.2,1)
- 完全消失后 DOM 移除（避免空容器占位）

### 4.3 不允许残留

- 数量 = 0 时角标必须**完全不渲染**
- 不允许"显示 0"或"显示空圆点"

## 五、Count Dot（红点）

### 5.1 触发显示

- 业务方传入 `dot=true`
- 不显示具体数字，仅红点提示"有更新"
- 适用于侧栏 / 顶栏导航的"次级提醒"

### 5.2 与 Count Number 的差异

| 维度 | Dot | Number |
|------|-----|--------|
| 信息量 | 仅有 / 无 | 具体数量 |
| 适用场景 | 次要通知 | 主要通知（如未读消息）|
| 视觉权重 | 低 | 高 |

### 5.3 清零

- 同 Number：数据为 0 时不显示
- 用户访问对应页面后清零（业务方控制）

---

## 六、Status Pill（表格状态列）

### 6.1 状态变更

| 变更 | 动画 |
|------|------|
| 文本变更 | 旧文本 fadeOut 100ms → 新文本 fadeIn 100ms |
| 颜色变更 | 背景色过渡 200ms |
| 状态升级（如"进行中"→"成功"）| 加上一次 scale 1→1.05→1 强调 |
| 状态降级（如"成功"→"失败"）| 加上一次抖动强调 |

### 6.2 多状态共存

- 同一行多个 Status Pill 时，垂直对齐
- 间距 4px

---

## 七、Ribbon（卡片角标）

### 7.1 触发

- 业务方传入 `ribbon` 配置
- 卡片右上角固定显示
- 不响应数字变化（通常是固定标签如"NEW" / "HOT"）

### 7.2 不动画

- Ribbon 默认无动画
- 业务方可启用入场动画（卡片首次出现时 ribbon 滑入 300ms）

---

## 八、键盘与无障碍

### 8.1 角标的 ARIA

- 数字角标：`aria-label="N 条未读"`
- 红点：`aria-label="有未读"`
- Ribbon：`role="status"` + `aria-label="新内容标记"`

### 8.2 不可独立聚焦

- 角标本身不应可 Tab 聚焦
- 焦点应落在父元素（按钮 / 链接）

### 8.3 屏幕阅读器

- 数量变化时通过 `aria-live="polite"` 通知
- 不要用 `assertive`（避免打断用户）

---

## 九、性能

### 9.1 高频更新

- 业务方实时推送（如 WebSocket）时，组件内部节流 100ms 合并
- 避免频繁触发 reflow

### 9.2 列表中大量 Badge

- 每行表格 / 列表项的 Badge 不能成为性能瓶颈
- 单次更新时只更新对应行，不重渲染整列

## 十、自检清单

- [ ] 数量为 0 时角标不显示
- [ ] 数量 1–99 显示实际数字
- [ ] 100–999 显示"99+"
- [ ] >999 显示"999+"
- [ ] 业务方 max 自定义生效
- [ ] +1 触发 scale 200ms 抖动
- [ ] 数字变小仅 fade 不抖动
- [ ] 100ms 内多次更新合并为一次动画
- [ ] 清零时角标淡出 + 缩小 200ms
- [ ] 清零后 DOM 完全移除
- [ ] Dot 模式不显示数字
- [ ] Status Pill 文本变更 fade 切换
- [ ] Status Pill 升级 / 降级有强调动画
- [ ] Ribbon 默认无动画（仅卡片入场可加）
- [ ] 角标不可独立 Tab 聚焦
- [ ] aria-label 正确
- [ ] aria-live="polite" 通知数量变化
- [ ] 高频更新节流 100ms

---

## 十一、不适用场景

- **价格 / 价格变动**：用 Tag 而非 Badge（金额不应"抖动"）
- **倒计时**：用专门的 Countdown 组件
- **持续状态指示**（如"录音中"）：用脉动 Dot 配合文字而非 Badge
- **关键警告**（必须用户关注）：用 Banner / Alert 而非 Badge（Badge 太克制）
