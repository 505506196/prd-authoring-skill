# 步骤条交互规范 — 已完成可回退 / 错误态恢复 / 异步进入下一步

> **本文件解决「已完成步骤不能修改」「错误态没有重试入口」「点击下一步要等接口但没有反馈」三类问题。**
>
> 视觉规范见 [`../../steps.md`](../../steps.md)。

---

## 一、设计目标

| 目标 | 表现 |
|------|------|
| **可回到已完成** | 已完成步骤可点击回退修改 |
| **不可跨越未完成** | 未到达的步骤不可直接点击进入 |
| **错误可识别可恢复** | 错误节点视觉明确，提供修正入口 |
| **异步切换有反馈** | "下一步"接口期间禁用 + Spinner |

---

## 二、节点点击规则

### 2.1 三种点击响应

| 节点状态 | 点击行为 |
|---------|---------|
| 已完成（completed）| **可点击**回退到该步骤，进入"修改模式" |
| 进行中（current）| 不响应（已经在该步骤）|
| 未开始（pending）| **不可点击**（cursor: default，无 hover 反馈）|
| 错误（error）| 可点击回到该步骤修正 |
| 禁用（disabled）| 不可点击 |

### 2.2 hover 反馈

| 节点状态 | hover |
|---------|-------|
| 已完成 / 错误 / 当前 | cursor: pointer + 主色光环（参考 steps.md 第五节）|
| 未开始 / 禁用 | cursor: default + 无变化 |

### 2.3 跨步骤点击

- 业务方可禁用"已完成步骤回退"（设置 `linear=true`）
- 设为线性时已完成步骤也不可点击
- 适用于审批流等不允许回退的场景

---

## 三、回退到已完成步骤

### 3.1 修改模式

| 元素 | 行为 |
|------|------|
| 该步骤的状态 | 临时改为"current"（进入修改）|
| 后续已完成步骤 | 全部保留为"completed"（数据未失效）|
| 顶部提示 Banner | "您正在修改第 N 步，修改后请确认"（可关闭）|

### 3.2 修改后的两种处理

| 用户操作 | 行为 |
|---------|------|
| 点击"保存修改" | 仅更新该步数据，不重置后续步骤；状态回到完成 |
| 点击"保存并重置后续" | 该步保存 + 后续步骤全部回退到"未开始" |
| 点击"取消修改" | 不修改，状态恢复 completed |

> 这是步骤条最容易踩坑的地方：**改了第 2 步是否要重置第 3、4 步**？必须由业务方明确选择，不能默认隐式行为。

---

## 四、未开始步骤的不可点击

### 4.1 视觉

- 节点 `--text-500` 字色，不响应 hover
- cursor: `default`（不是 `not-allowed`，避免暗示"被禁用"——只是顺序问题）

### 4.2 hover Tooltip

- hover 时显示 Tooltip："请先完成第 N 步"
- 触发延迟 300ms（同 [`../../tooltip/interaction/trigger-positioning.md`](../../tooltip/interaction/trigger-positioning.md)）

### 4.3 键盘

- 未开始步骤 `tabindex="-1"`，不可 Tab 聚焦
- 仅"已完成"和"当前"步骤可 Tab

---

## 五、错误态

### 5.1 触发场景

| 触发 | 行为 |
|------|------|
| 步骤接口失败 | 该步骤切换为错误态（红色 + x 图标）|
| 表单校验失败 | 同上 |
| 业务规则不通过 | 同上 |

### 5.2 视觉与 Steps.md 一致

- 节点：`--danger-500` 实色 + x-mark 白色图标
- 连接线（错误段）：保持原 `--border` 不变（错误不传染）
- 标题色：`--danger-600` Semibold
- 描述：`--danger-500`

### 5.3 错误恢复

- 错误节点点击后进入修改模式（同已完成步骤）
- 修正后该节点恢复 completed 或 current（视实际进度）
- 错误描述应给出具体原因："邮箱格式不正确"，而不是"步骤错误"

## 六、异步"下一步"

### 6.1 提交流程

```
点击"下一步"按钮
  ├─ 按钮进入 loading（参考 button/interaction/loading-state.md）
  ├─ 当前步骤不变化视觉
  ├─ 调用接口
  │   ├─ 成功 → 当前步骤切换为 completed，下一步切换为 current
  │   └─ 失败 → 当前步骤切换为 error，按钮恢复，Toast 错误
  └─ 期间禁止重复点击
```

### 6.2 步骤切换动画

| 阶段 | 过渡 |
|------|------|
| 完成态填充 | 节点背景从白色 fade 到主色 200ms |
| Check 图标 | `stroke-dashoffset` 200ms 描出 |
| 连接线 | 从 `--border` 渐变到 `--primary-600` 300ms（从左到右）|
| 下一节点切换 | 与连接线同步 |

### 6.3 进度感知

- 整个步骤条切换总时长 ≤ 500ms（避免拖沓）
- 切换期间右侧"下一步"按钮 disabled，防止重复触发

## 七、Dot 迷你版

### 7.1 适用场景

- 列表行内进度（占据空间小）
- 卡片角落简明进度

### 7.2 行为

- 不可点击（仅展示）
- hover 时显示 Tooltip 当前阶段名称
- 错误态用红色 dot 而非 x 图标

---

## 八、表单分步

### 8.1 与 Form 集成

| 维度 | 规则 |
|------|------|
| 每步对应一个 Form 子表单 | 切换步骤时不卸载已填字段 |
| "下一步"前自动校验当前 Form | 校验失败不允许进入下一步 |
| 校验失败的字段聚焦 | 自动滚动到第一个错误字段 |

### 8.2 数据保留

- 用户填到第 3 步又回到第 1 步：第 1 步已填字段保留
- 修改第 1 步后：弹出确认"修改后第 2、3 步数据是否保留？"

### 8.3 离开提示

- 表单分步未完成时，关闭页面 / 路由切换前提示"未保存的内容会丢失"
- 详见 `.claude/runtime-interaction-spec.md`（运行时交互细则）

---

## 九、垂直 Steps 的差异

| 维度 | 横向 | 竖向 |
|------|------|------|
| 连接线 | 水平 2px | 垂直 2px |
| 节点位置 | 水平居中 | 垂直左对齐 |
| 标题位置 | 节点下方 | 节点右侧 12px |
| 描述位置 | 标题下方 | 标题下方 |
| 项间距 | 自适应宽度 | 上下 24px |

> 竖向 Steps 适合长流程（>5 步）或带复杂描述的场景。

## 十、键盘交互

| 按键 | 行为 |
|------|------|
| Tab | 在可点击节点（completed / current / error）间切换 |
| Enter / Space | 触发节点点击（回退到该步骤）|
| ArrowLeft / ArrowRight | 横向 Steps 中移动焦点（不切换状态）|
| ArrowUp / ArrowDown | 竖向 Steps 中移动焦点 |

## 十二、不适用场景

- **持续状态展示**（如订单进度）：用 Timeline 或 Progress 而非 Steps
- **超过 8 步**：建议拆分为 wizard 或多页
- **状态非线性**（多分支可同时进行）：用流程图而非 Steps
- **极简引导**（仅 2 步）：用 Tabs 或单页表单
